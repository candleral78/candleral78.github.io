사용자: 라엘(컨설턴트 1인). 시험 운영 기간에는 업체 대표에게 앱을 열지 않는다.

## 1. 제품 정의

업체 정보와 업체 가이드를 기준으로 발행 전 원고와 발행된 글을 검수하고, **원본의 해당 부분을 보여 주며 무엇을 어떻게 고칠지 분명하게 요청하는 첨삭지**를 만든다. 모든 지적에는 근거(조회 시각, 출처, 링크, 기록)가 붙는다.

## 2. 기술 구성

기존 블로그 글쓰기 앱의 구조를 재사용한다.

- 화면: GitHub Pages (`candleral78.github.io/blog-writer/`), 검수 전용 진입은 `?r`. 글꼴은 Gmarket Sans
- 서버: Apps Script (`Code.gs`에 `fetchPost`, `fetchRss`, `fetchKeywordEvidence`, `reviewPost` 추가)
- 저장: 구글 시트 탭 추가 — `criteria`, `core_keywords`, `keyword_review`, `reviews`, `findings`, `keyword_log`, `posts`
- AI: Gemini (문장 판단, 캡처 속 문제 위치 좌표)
- 외부 API: 네이버 검색광고 API(키워드 도구), 네이버 개발자센터(블로그 검색, 데이터랩). 키는 라엘 계정 1개씩, 스크립트 속성에 저장

## 3. 개발 범위

| 단계 | 범위 | 완료 조건 |
| --- | --- | --- |
| 0 | Apps Script 수집 시험: RSS, 모바일 글 본문, 블로그 검색 결과, 플레이스, 검색광고 API, 블로그 검색 API | 6가지 각각 성공/실패와 응답 형태를 시트에 기록. 실패 항목은 대체 방법(캡처 업로드) 확정 |
| 1 | 업체 등록(핵심 키워드 포함), 기준표, 원고·링크·캡처 입력, 기계 검사, **당일 키워드 근거**, AI 첨삭, **첨삭지와 내보내기**, 검수 이력 | 실제 업체 글 10편을 검수해 모든 카드에 원본 캡처와 근거가 붙고, 라엘이 수정 없이 보낼 수 있는 카드 비율을 기록 |
| 2 | RSS 새 글 감지, 중복 방지, 재검수, 30일 핵심 키워드 재점검, 월간 요약 | 같은 글이 두 번 검수되지 않고, 수집 실패가 목록에 보이며, 월간 요약의 모든 문장이 검수 상세로 연결됨 |
| 3~5 (확장) | 데이터랩 추이, 통계 캡처 가져오기, 크롬 확장, 로그인 통계, 플레이스·스마트스토어 기준표 | 1·2단계 시험 결과를 보고 재정의 |

## 4. 입력

| 입력 | 처리 | 원본 캡처 만드는 방법 |
| --- | --- | --- |
| 원고 붙여넣기 | 제목, 문단 분리. `[사진]`, `[지도]` 표시를 배치 계획으로 인식 | 원고를 블로그 모양으로 다시 그린 화면에서 해당 부분을 이미지로 자름 |
| 발행 글 링크 | `m.blog.naver.com/아이디/글번호`로 바꿔 수집. 에디터 요소(`se-component se-*`)를 종류별로 셈 | 수집한 구조로 다시 그린 화면 + 사진은 원본 이미지 사용 |
| 캡처·PDF (여러 장) | 순서대로 이어 붙여 한 장으로 취급. Gemini가 텍스트와 문제 위치 좌표 반환 | 실제 화면에서 좌표대로 잘라 빨간 박스. 라엘이 박스를 끌어 조정 가능 |

다시 그린 화면은 실제 네이버 화면과 줄바꿈과 글자 크기가 다를 수 있으므로 첨삭지에 "재구성 화면"으로 표기한다. 캡처 입력은 "실제 화면"으로 표기한다.

## 5. 기준표 (`criteria` 탭)

블로그 포스팅 스마트에디터 ONE 최적화 테이블(26개 항목)을 초안으로 등록한다. 스마트2.0 시트는 사용하지 않는다.

| 칸 | 내용 |
| --- | --- |
| 항목 | 예: 사진, 지도, 인용구, 글자 수, 업체 정보, 금지 표현 |
| 글 유형 | 방문 후기, 상품 소개, 행사 안내, 정보성 |
| 업체별 구분 | 필수 / 권장 / 선택 (업체 가이드에 있는 것만 필수) |
| 판정 방법 | 기계 / AI / 라엘 확인 |
| 조건 | 예: 공백 제외 본문 1,500자 이상(제목·사진 설명 제외) |
| 근거 출처 | 업체 가이드 번호, 법령·지침 조항, 내부 편집 기준 |
| 버전 | 변경일, 변경 이유 |

특수문자 삽입, 지식백과, 수식으로 전화번호 노출처럼 효과 근거가 없는 항목은 기본값을 "선택"으로 둔다.

## 6. 검사

### 기계 검사 (AI 미사용)
글자 수, 사진·동영상·지도·인용구·구분선·표·링크·스티커 개수와 위치, 키워드 위치와 반복 횟수, 업체 정보(주소·전화·영업시간·가격) 대조, 금지·주의 표현 사전, 대가성 문구 텍스트, 지정 링크 존재와 응답. 읽지 못한 요소는 "확인 불가"로 남기고 0으로 세지 않는다.

### 생성형 AI 이미지 표시 (1단계)

앱은 AI 이미지를 확실하게 가려낼 수 없다(네이버 업로드 과정에서 메타데이터가 사라질 수 있고, 눈으로 보는 판단은 틀릴 수 있다). 그래서 **대표자 확인 질문 + 화면 단서**로 판정한다.

1. 검수 입력 때 질문: "이 글에 AI로 만든 이미지가 있나요? 있다면 몇 번째 사진인가요? 사람(인물)이 나오나요?"
2. 화면 단서: 눈에 보이는 AI 워터마크, 사진 설명이나 본문의 "AI" 표기, 네이버 'AI 활용' 표시(수집 가능 여부는 0단계에서 확인). 단서만으로는 "추가 확인"까지만 표시한다.

| 경우 | 기준 출처 | 구분 | 첨삭 내용 |
| --- | --- | --- | --- |
| AI 가상인물이 상품·가게를 추천·보증하는 글 | 공정위 추천·보증 심사지침(2026.6.1 개정 시행) | 필수 | 제목이나 본문 첫 부분에 "AI로 생성한 가상인물이 포함된 게시물입니다", 해당 이미지의 인물 가까이에 "가상인물" 표시. 이미지 하단 설명만으로는 부족할 수 있음. 실제 사용 경험처럼 쓴 추천 문장은 따로 지적 |
| AI로 만든 음식·매장·상품·시술 결과 이미지가 실제처럼 보이는 경우 | 표시광고법(거짓·과장, 기만 광고 위험), 업체 기준 | 필수(업체 기준) | 해당 사진 바로 아래 사진 설명에 "AI로 만든 이미지로, 실제와 다를 수 있습니다". 실제 사진으로 바꾸기를 우선 권함 |
| 의료·건강기능식품·식품·의료기기 업종에서 AI로 만든 전문가(의사·약사 등) | 식품표시광고법·약사법(2026.11.27), 의료기기법(2026.12.10) 개정 시행 예정 | 필수 | 표시로 해결되지 않음. 해당 이미지와 문장 삭제를 요청 |
| 분위기용 일러스트, 안내 그래픽 등 실제로 오해할 여지가 적은 이미지 | 네이버 'AI 활용' 표시(권장 기능), AI 기본법 흐름 | 권장 | 사진 설명에 "AI 생성 이미지" 또는 네이버 AI 활용 표시 |

- 판정 근거 칸에 적용한 기준과 시행일을 적는다. 법 해석이 필요한 사례는 "추가 확인"으로 두고 단정하지 않는다.
- 기준이 바뀌는 분야이므로 이 표는 `criteria`에 버전으로 관리하고, 분기마다 법령·지침 변경을 확인한다(정보통신망법 AI 생성물 표시 개정안은 2026.10 현재 국회 심사 중).

### 당일 키워드 근거 (1단계 필수)
키워드에 대한 모든 지적은 아래 기록을 `keyword_log`에 저장하고 카드의 근거 칸에 넣는다.

| 근거 | 출처 | 표기 |
| --- | --- | --- |
| 월간 검색량 PC/모바일, 연관 키워드 | 검색광고 API | "2026.10.17 조회, 최근 30일 기준". "10 미만" 같은 구간값은 그대로 표기 |
| 블로그 검색 결과 수, 상위 글 목록(제목·블로그명·작성일·링크) | 블로그 검색 API | "API 기준 상위 글" |
| 실제 화면 상위 글 | 모바일 검색 화면 수집(보조) | 실패하면 "확인 불가", 라엘 캡처 첨부 칸 제공 |
| 검색 결과 바로가기 링크 | 네이버 검색 주소 | "누르면 현재 결과가 열림" 안내 |

- 같은 키워드는 하루 1회만 조회하고 재사용한다.
- 근거가 비어 있는 키워드 지적은 "추가 확인"으로 내린다.
- 같은 키워드를 나중에 다시 조회하면 전후 비교에 쓴다.

### AI 첨삭 (Gemini 1회 호출)
제목과 본문 일치, 검색한 사람의 궁금증 해소, 경험 정보, 문장 반복과 흐름, 맞춤법, 말투, 사진과 본문의 관련성. 반드시 원문 인용 위치를 반환하게 하고, 인용 위치를 원문에서 찾지 못한 지적은 버린다. 수정안에 확인되지 않은 가격, 방문 경험, 행사 조건을 넣지 않는다.

## 7. 첨삭지 (핵심 결과물)

### 첨삭 카드

```
② 수정 필요 · 업체 정보
[원본 캡처 — 문제 부분 빨간 박스] (실제 화면 / 재구성 화면 표기)
코멘트: 본문에는 영업시간이 오전 10시로, 플레이스에는 오전 11시로 되어 있습니다.
        이 글을 보고 일찍 오신 손님이 헛걸음하실 수 있어 꼭 맞춰 주셔야 합니다.
        본문을 아래처럼 고쳐 주세요.
수정안: 영업시간은 오전 11시부터 오후 9시까지입니다.   [복사]
근거:   플레이스 조회 2026.10.17 09:12 · 링크 · 해당 화면
```

코멘트 원칙 (받는 사람은 대표자)
- 순서는 **사실 → 이유(손님 입장) → 요청**. 무엇이 어떻게 되어 있는지 먼저 쓰고, 왜 고쳐야 하는지 한 문장, 마지막에 무엇을 해 달라는지 쓴다.
- 존댓말은 정중하게, 요청은 분명하게 쓴다. "~하세요"(지시), "~하는 게 어떨까 싶습니다"(모호함) 둘 다 쓰지 않는다.
- 판정에 따라 끝맺음을 나눈다.

| 판정 | 끝맺음 | 예 |
| --- | --- | --- |
| 수정 필요 (사실 오류, 표시광고·의료광고 등 법적 위험, 업체 가이드 필수) | "~해 주셔야 합니다", "~로 고쳐 주세요" | 영업시간을 플레이스와 맞춰 주셔야 합니다 |
| 수정 필요 (그 밖의 필수 항목) | "~해 주세요" | 마지막 문단 뒤에 지도를 넣어 주세요 |
| 권장 | "~하시면 ~합니다. ~을 권해 드립니다" | 제목 앞쪽에 '의정부역'을 넣으시면 역 근처에서 찾는 분들께 더 잘 보입니다 |
| 추가 확인 | "~인지 알려 주시면 ~하겠습니다" | 협찬을 받으신 글인지 알려 주시면 표기 문구를 맞춰 드리겠습니다 |

- 대표자를 탓하는 표현(틀렸습니다, 잘못 쓰셨습니다, 부족합니다)은 쓰지 않는다. 글의 상태를 설명한다.
- 전문 용어(키워드 밀도, 체류시간, 상위노출 로직)는 쓰지 않고 손님 행동으로 바꿔 쓴다.
- 사진 지적은 그 사진을 카드에 붙인다.
- 근거 칸이 빈 카드는 "수정 필요"로 표시할 수 없다.
- 첨삭지 맨 앞에는 **잘된 점 1~2가지**를 근거와 함께 먼저 쓴다(예: "사진 12장이 모두 직접 찍은 매장 사진이라 방문 전 분위기가 잘 전해집니다"). 칭찬할 근거가 없으면 지어내지 않는다.

### 첨삭지 구성 (위에서부터)

**① 안내 문구 (항상 맨 위, 삭제 불가)**

> 이 첨삭지는 정답을 정해 드리는 것이 아니라, 검수 기준과 조회 자료를 바탕으로 드리는 컨설턴트의 의견입니다. 대표님 업체의 사정이나 의도와 다른 부분이 있다면 그대로 두셔도 괜찮고, 말씀해 주시면 다음 검수에 반영하겠습니다. 검색 결과와 검색량은 조회한 시점의 자료이며, 이 의견을 따르더라도 검색 노출이 보장되지는 않습니다.

**② 요약:** 꼭 고쳐 주실 것 ○건, 권해 드리는 것 ○건, 확인이 필요한 것 ○건. 영역별(품질·검색 적합성·가이드 준수) 상태. 종합점수 없음

**③ 잘된 점 1~2가지** (근거 포함, 근거 없으면 생략)

**④ 핵심 키워드 현황** (아래 7-1)

**④-2 발행 전 체크리스트** (아래 7-0, 앱 확인 결과 미리 표시)

**⑤ 전체 첨삭지:** 원고 전체에 ①②③ 번호와 빨간 표시

**⑥ 첨삭 카드:** 번호 순서

**⑦ 하단:** 검수일, 사용한 기준 버전, 검색 자료 조회 시각

라엘 확인 화면: 카드별 코멘트 수정, 박스 조정, 카드 삭제, 보낼 카드 선택. 안내 문구는 수정할 수 있으나 삭제할 수 없다.

### 7-0. 발행 전 체크리스트 (대표자용, 체크박스)

대표자가 글을 올리기 전에 직접 체크하는 목록. 업체 등록 정보로 미리 채워서 내보낸다(플레이스 주소, 상호, 전화, 영업시간, 핵심 키워드가 칸에 적혀 있음). 쓰임은 두 가지다.

1. **단독 체크리스트:** 업체별 1장(카카오톡 이미지 / PDF / 인쇄용). 대표자가 휴대폰에 저장해 두고 글 올릴 때마다 본다.
2. **첨삭지 안의 체크리스트:** 검수한 글 기준으로 앱이 확인한 항목은 ✅ 또는 ❌로 미리 표시하고, 앱이 확인할 수 없는 항목만 빈 체크박스(☐)로 남긴다.

각 항목 옆에 확인 주체를 표시한다: [앱] 앱이 자동 확인 / [대표] 대표자가 직접 확인. 업체별로 자주 놓친 항목(검수 기록 기준 상위 3개)은 굵게 표시하고 맨 위로 올린다.

**업체 정보 (플레이스와 같아야 합니다)**
- [ ] 상호명이 플레이스와 같습니다 — 플레이스 상호: `{상호}` [앱]
- [ ] 장소(지도)를 첨부했고, 플레이스에 등록된 우리 가게로 선택했습니다(이름이 비슷한 다른 지점이 아닌지 확인) — `{플레이스 주소 링크}` [앱]
- [ ] 플레이스 링크 또는 예약·주문·톡톡 링크를 넣었습니다 [앱]
- [ ] 주소, 전화번호가 플레이스와 같습니다 — `{주소}` / `{전화}` [앱]
- [ ] 영업시간, 휴무일, 브레이크타임, 라스트오더가 플레이스와 같습니다 [앱]
- [ ] 주차와 찾아오는 길을 적었습니다(해당 업종) [대표]
- [ ] 가격과 메뉴가 현재 기준입니다 [대표]
- [ ] 이벤트·할인은 기간과 조건을 적었습니다 [대표]

**제목과 본문**
- [ ] 제목이나 첫 문단에 상호가 들어 있습니다 — `{상호 키워드}` [앱]
- [ ] 이번 글에 맞는 핵심 키워드를 자연스럽게 넣었습니다 — `{핵심 키워드 목록}` [앱]
- [ ] 첫 문단만 읽어도 무엇에 대한 글인지 알 수 있습니다 [대표]
- [ ] 소제목이나 인용구로 내용을 나눴습니다 [앱]
- [ ] 마지막에 예약·문의·찾아오는 방법을 안내했습니다 [앱]

**사진과 영상**
- [ ] 직접 찍은 사진을 썼고, 첫 사진이 이 글을 가장 잘 보여 줍니다 [대표]
- [ ] 다른 글에서 쓴 사진을 그대로 반복하지 않았습니다 [앱]
- [ ] 주요 사진에 사진 설명을 적었습니다 [앱]
- [ ] AI로 만든 이미지가 있다면 표시했습니다(인물이 나오면 제목·첫 부분과 인물 옆에 표시) [대표]
- [ ] 손님 얼굴, 차량 번호 등 다른 사람의 정보가 보이지 않습니다 [대표]

**표시와 주의 표현**
- [ ] 협찬·지원·체험단 글이면 제목이나 첫 부분에 표기했습니다 [대표]
- [ ] 효과를 장담하는 표현(완치, 100%, 부작용 없음, 최고 등)을 쓰지 않았습니다 [앱]
- [ ] 다른 사람의 사진·글·글꼴을 허락 없이 쓰지 않았습니다 [대표]

**발행 설정**
- [ ] 카테고리를 맞게 골랐습니다 [대표]
- [ ] 태그에 상호와 핵심 키워드를 넣었습니다 [앱]
- [ ] 공개 설정이 '전체공개'입니다 [대표]
- [ ] 검색 허용과 외부 보내기 허용이 켜져 있습니다(꺼져 있으면 검색과 자동 검수에서 빠질 수 있음) [대표]
- [ ] 네이버 맞춤법 검사를 했습니다 [대표]
- [ ] 모바일 미리보기로 사진과 글이 잘 보이는지 확인했습니다 [대표]

규칙
- 체크리스트 항목은 `criteria` 탭과 같은 기준을 쓴다. 업체 가이드에서 "선택"인 항목은 업체별로 숨길 수 있다.
- 업종별로 항목을 더한다(예: 음식점 — 원산지·알레르기 안내, 미용·시술 — 시술 전후 사진 사용 주의, 숙박·레저 — 예약·환불 규정).
- 앱 화면에서는 체크박스를 누를 수 있고, 대표자가 체크한 결과를 받으면 해당 글 검수 기록에 함께 저장한다(1인 시험 단계에서는 라엘이 대신 입력).

### 7-1. 핵심 키워드 (업체가 계속 가지고 가야 할 키워드)

업체 등록 때 라엘이 정하고, 모든 글의 검수와 첨삭지에 기준으로 쓴다. 시트 `core_keywords` 탭에 저장한다.

| 구분 | 예 (의정부역 브런치 카페) | 쓰임 |
| --- | --- | --- |
| 상호 키워드 | 카페○○, 카페○○ 의정부 | 모든 글 제목 또는 첫 문단에 1회 |
| 지역 + 업종 대표 키워드 | 의정부역 브런치 카페 | 대부분의 글에 사용 |
| 대표 상품·서비스 키워드 | 의정부 수제 샌드위치 | 해당 상품을 다루는 글 |
| 차별점 키워드 | 의정부 애견동반 카페 | 업체가 계속 알려야 할 강점 |

각 키워드에 저장할 것: 선정 이유, 등록일, 최근 조회 검색량(PC/모바일, 조회 시각), 블로그 글 수, 플레이스 대표키워드와 일치 여부, 사용 구분(모든 글 / 해당 글만), 다음 재점검일(등록일 또는 마지막 점검일 + 30일).

#### 30일 핵심 키워드 재점검

30일마다 자동으로 다시 조회해 `keyword_review` 탭에 기록하고, 라엘이 확정한다. 앱이 키워드를 스스로 바꾸지 않는다.

| 다시 확인하는 것 | 출처 |
| --- | --- |
| 최근 30일 검색량 PC/모바일과 지난 점검 대비 변화 | 검색광고 API |
| 블로그 글 수와 상위 글 목록 변화 | 블로그 검색 API |
| 플레이스 대표키워드가 바뀌었는지, 블로그 핵심 키워드와 맞는지 | 플레이스 수집 |
| 연관 키워드 중 새로 검색량이 붙은 것 | 검색광고 API |
| 지난 30일 동안 업체 글에서 실제로 쓴 횟수 | 검수 기록 |

점검 결과는 키워드마다 **유지 / 교체 검토 / 추가 후보** 중 하나로 제안하고 근거를 붙인다.
- 한 번의 하락만으로 교체를 제안하지 않는다. 두 번 연속(60일) 떨어졌거나 계절 요인이 아닌 것이 확인될 때 "교체 검토"로 둔다.
- 플레이스 대표키워드가 바뀌었으면 블로그 핵심 키워드와의 차이를 바로 표시한다.
- 라엘이 확정하면 변경 이력(이전 키워드, 바꾼 날, 이유)을 남기고, 다음 첨삭지부터 새 기준을 쓴다. 이전 첨삭지는 당시 기준 그대로 보존한다.
- 대표자에게는 변경이 있을 때만 "이번 달 핵심 키워드 안내" 한 장을 보낸다.

| --- | --- | --- | --- |

- 상호 키워드가 빠진 글은 "꼭 고쳐 주실 것"으로, 나머지 핵심 키워드는 글 유형에 맞을 때만 "권해 드리는 것"으로 표시한다.
- 핵심 키워드를 억지로 여러 번 넣으라는 의견은 내지 않는다. 같은 키워드 반복은 기계 검사에서 따로 본다.
- 월간 요약에 핵심 키워드별 사용 글 수와 검색량 변화를 넣는다.
- 핵심 키워드는 블로그 글쓰기 앱의 업체 정보와 공유해, 글을 쓸 때와 검수할 때 같은 키워드를 쓴다.

## 9. 2단계: 자동 감지와 월간 요약

- 업체별 블로그 RSS(`https://rss.blog.naver.com/아이디.xml`)를 하루 1~2회 확인. 글 번호로 중복 판단
- 새 글은 기계 검사와 키워드 근거를 자동 실행, AI 첨삭은 하루 한 번 몰아서 실행. 한도 초과 시 "AI 대기"로 표시
- 컨설턴트 화면에 "새 검수 결과" 목록과 처리 상태(수집 실패, AI 대기, 확인 전, 발송함)
- 월간 요약: 확인한 글 수, 필수 미충족 글 수, 반복된 문제 상위 3개, 개선된 항목, 키워드 전후 비교. 모든 문장은 해당 검수 상세로 연결
- RSS로 찾은 글 수를 업체 전체 발행 수로 표기하지 않음

## 10. 시험 계획

1. 0단계 수집 시험을 Apps Script에서 실행하고 결과를 기록한다.
2. 관리 중인 업체 블로그 글 10편(발행 전 원고 3편 포함)으로 1단계를 시험한다.
3. 기록할 것: 카드별 라엘 수정 여부, 잘못된 지적 수, 박스 위치 오류 수, 근거 누락 수, 1편당 처리 시간, AI 호출 수.
4. 결과를 보고 대표 공개 여부와 3단계 이후 범위를 정한다.
